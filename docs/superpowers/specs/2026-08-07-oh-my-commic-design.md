# oh-my-commic 设计文档

- **日期**: 2026-08-07
- **性质**: 48 小时面试作品
- **一句话**: 面向小朋友 & 亲子的 AI 漫画书制作 Web 应用——用户建一本书、创建角色与场景、用一句话+对话生成分镜、逐格出图、拼版成一本漫画书。

---

## 1. 背景与目标

### 目标用户
小朋友与家长（亲子共创）。交互要简单、可视、鼓励式，风格温暖（吉卜力/宫崎骏）。

### 产品目标
让不会画画的用户，通过"讲故事 + 和 AI 聊分镜 + 一张张生图"的方式，做出一本属于自己的漫画书。

### 面试要展示的三个技术亮点
1. **多用户 context 管理与隔离**——每个用户的书/资产/章节严格隔离。
2. **AI 索引资产**——AI 读故事，自动决定每个分镜出场哪些角色、用哪个场景。
3. **参考图锁定角色一致性**——用户上传的角色/场景图作为参考图，保证同一角色跨分镜形象一致。

### 非目标（48h 内明确不做）
支付/会员、多风格切换、实时协作、移动端专门适配、复杂连环画错落排版。

## 2. 核心组织结构与数据模型

**Book 是顶层单元**：一本漫画书拥有自己的"演员表（角色/场景）"和多个"章节（故事）"，章节由多张分镜图组成。

```
User
 └─ Book  (一本漫画书 = 顶层单元, 自带角色宇宙+世界观)
     ├─ Character  (角色/宠物, 跨章节复用)
     ├─ Scene      (场景, 跨章节复用)
     └─ Chapter    (故事/章节, 有序)
         └─ Panel  (pic1, pic2… = 分镜)
```

### 数据表

```yaml
User:      id, 昵称, 密码hash, 创建时间

Book:      id, user_id, 标题, 封面URL, 风格(默认:吉卜力), 简介,
           is_public(分享/点赞→后做), 创建时间, 更新时间

Character: id, book_id, type(角色|宠物), 名字, 性别, 年龄, 性格, 描述,
           图片URL(用户上传, 同时作为锁定形象+参考图)

Scene:     id, book_id, 名字, 描述, 图片URL(用户上传, 作为参考图)

Chapter:   id, book_id, 序号, 标题, 状态(草稿|分镜中|出图中|完成), 创建时间

Panel:     id, chapter_id, 序号, 画面描述, 角色ids[](JSON), 场景id,
           生图prompt, 图片URL, 状态(待生成|生成中|已完成|失败)
```

> **隔离原则**：除 User 外每张表都能追溯到 `user_id`（Book 直接挂 user_id，其余通过 book_id/chapter_id 级联）。所有读写都必须校验归属。

## 3. 端到端流水线

```
① 建书          用户新建一本 Book(标题/风格)
② 建资产        在 Book 下创建 角色/宠物/场景：上传图片 + 填设定
③ 新建章节      在 Book 下新建 Chapter
④ 对话出脚本    用户输入一段简单介绍 → 与 AI 多轮对话打磨 → 产出一组分镜文字描述
⑤ AI 索引       为每个分镜自动标注：出场角色 + 使用场景（用户可微调）
⑥ 逐格生图      每格 = 吉卜力风格前缀 + 画面描述 + 命中角色/场景的参考图
                → 千问生图 → 得到该格图片（保证角色一致）
⑦ 拼版成页      多张分镜图按网格模板拼成漫画页 → 保存成章
⑧ 阅读          在阅读页翻页查看整本漫画书
```

## 4. 前端页面（6 个）

每个页面单一职责。P5 是投入最多的核心。

```yaml
P1 登录注册页
   职责: 昵称+密码 登录/注册，唯一入口
   模块: [登录表单, 注册表单]

P2 书架主页 (Home)
   职责: 展示"我的书"封面墙 + 新建书入口
   模块: [我的书-封面网格, ＋新建书, (公开广场-后做占位)]

P3 Book 工作台
   职责: 一本书的中枢——管演员、管章节
   模块: [书信息头, 演员表面板(角色/宠物/场景 + ＋新建), 章节列表面板(+新建章节)]

P4 资产编辑页 (独立页面, 极简)
   职责: 创建/编辑一个角色或场景
   模块:
     角色/宠物: [上传图片(锁定形象/参考图), 表单(名字/性别/年龄/性格/描述), 保存]
     场景:      [上传图片(参考图), 表单(名字/描述), 保存]

P5 Chapter 编辑器 (核心, 3 阶段)
   阶段A 对话式生成分镜脚本:
     [故事介绍输入框, 人机多轮对话区, "产出分镜脚本"按钮 → 一组分镜描述]
   阶段B 逐格生图:
     [分镜卡列表; 每卡: 画面描述 + 自动索引到的角色/场景(可微调) + 「生成这张图」+ 单格重生成]
   阶段C 拼接成页:
     [网格模板拼版预览, 保存成章]

P6 漫画阅读页 (Reader)
   职责: 翻页阅读成品漫画书(只读)
   模块: [翻页画布, 章节切换, (导出/分享-后做)]
```

### 页面导航
```
P1 登录 → P2 书架 → (点书)P3 Book工作台 → (点章节)P5 Chapter编辑器
                              ├→ (点资产)P4 资产编辑
                              └→ (点已完成章节)P6 阅读
```

## 5. 后端模块（Go，分层：handler → service → repository）

```yaml
M1 auth       注册/登录/session + 隔离中间件(强制注入并校验 user_id)
M2 book       Book CRUD + 归属校验
M3 asset      角色/宠物/场景 CRUD + 图片上传落地
M4 chapter    Chapter CRUD + 状态机(草稿→分镜中→出图中→完成)
M5 panel      分镜增删改排序 + 保存 prompt/图片/状态
M6 ai-gateway 封装千问(最核心):
                - 文本编排: 对话打磨脚本 + 故事+资产库→结构化分镜(AI索引)
                - 生图: 风格前缀+描述+参考图 → 图片
M7 storage    图片落地(本地目录/对象存储)，返回可访问 URL
M8 compose    分镜图按模板拼版成页(可前端实现)
```

### 页面 ↔ 模块对应
```
P1→M1 | P2→M2 | P3→M2+M3+M4 | P4→M3+M7 | P5→M4+M5+M6+M7+M8 | P6→M4+M5
```

## 6. AI 集成（通义千问 DashScope）

统一用一个 provider（DashScope），key 存 `.env`。

### 6.1 文本编排（分镜脚本）
- **模型**: 千问文本模型（qwen 系列，如 `qwen-plus`/`qwen-max`）。
- **阶段A 对话**: 后端维护会话上下文，输入=用户介绍+历史对话+本书资产清单摘要，输出=AI 的下一句/修改建议。
- **产出分镜**: 用户满意后，调用一次"结构化输出"，返回分镜数组，每项含：`画面描述`、`命中角色ids`、`场景id`、`生图prompt`。这一步就是 **AI 索引角色/场景**。

### 6.2 生图（每个分镜一张）
- **模型**: 主力 `wan2.7-image-pro`（支持参考图/组图、控制力强）；`qwen-image` 系列备选。模型 id 走 env 可配置。
- **Prompt 结构**: `[吉卜力风格固定前缀] + [分镜画面描述] + [出场角色的设定摘要]`。
- **一致性**: 把命中角色/场景的**上传图片作为参考图**传入，锁定形象。
- **调用方式**: 生图为异步任务时，后端提交→轮询→拿到图 URL→落 M7→写回 Panel。前端对单格显示"生成中"骨架。

### 6.3 风格
先只做**吉卜力/宫崎骏**：用固定风格前缀（暖色、手绘水彩、柔和光影、圆润造型、亲子友好）。风格前缀集中管理，便于后续扩展。

## 7. 多用户隔离策略

- **认证**: session cookie（或 JWT）。中间件解析出 `user_id` 注入 request context。
- **授权**: 每个 repository 查询强制带 `user_id` 条件；Book 级资源校验 `book.user_id == 当前用户`，章节/分镜/资产通过外键级联校验。
- **越权防护**: 任何按 id 访问的资源，先校验归属，否则 404（不泄露存在性）。
- **图片存储**: 按 `user_id/book_id/...` 分目录，避免路径穿越。

## 8. 技术栈与架构

```
前端: React + Vite + TypeScript + Tailwind (SPA)   ← 由 Claude 全包
       └─ 与后端 JSON API 交互；页面结构以 YAML 图和用户对齐
后端: Go + chi(或 net/http)   分层 handler→service→repository
存储: SQLite (开发迭代快) + 本地文件目录存图片
AI:   DashScope 千问   文本(qwen) + 生图(wan2.7-image-pro)
配置: .env (含 DASHSCOPE_API_KEY)，.gitignore 排除
```

单体架构，优先"快速跑通 + 易演示"，不引入分布式复杂度。

## 11. 风险与对策

| 风险 | 对策 |
|---|---|
| 角色跨分镜不一致 | 上传图作参考图；风格前缀固定；必要时同角色复用 seed |
| 生图慢/失败 | 异步+轮询+骨架占位；失败可单格重试；不阻塞其他格 |
| AI 索引错角色 | 阶段B 允许用户手动增删命中角色/场景 |
| 48h 时间不够 | 严格按 MoSCoW，先跑通 Must 主线再加 Should |
| API key 泄露 | .env + .gitignore；文档提示面试后重置 key |

## 12. 安全

- API key 只存 `.env`，永不进 git（`.gitignore` 排除）。
- 用户上传图片校验类型/大小；存储按用户分目录防路径穿越。
- 密码 bcrypt 哈希；session 校验；越权返回 404。
